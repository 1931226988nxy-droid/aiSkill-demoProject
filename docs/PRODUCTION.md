# 生产部署与剩余外部事项

## 已落实的应用保护

- 工作台按当前会话权限筛选统计、读者借阅与预约数据。读者自助接口同时检查角色和权限；重新启动不会恢复管理员撤销的授权。
- 借还接口默认返回脱敏手机号和身份证。只有读者管理权限可以通过读者管理接口读取完整资料。
- 登录按账号与来源 IP 限流（15 分钟内账号最多 10 次、IP 最多 60 次）；注册按 IP 最多 10 次。计数保存到 SQLite，成功登录清除账号计数，IP 窗口保留。响应 429 提供 Retry-After。此机制适用于当前单实例架构。
- 登录、自助注册和修改密码使用异步 scrypt，并限制并发计算数量。初始建库和受信管理操作仍保留同步哈希函数。
- 会话固定有效期 7 天，空闲 30 分钟失效，通知后台轮询不延长空闲时间；账号停用、用户角色分配变更会撤销已有会话。权限调整每次请求实时读取。
- API 响应禁止缓存；变更请求检查浏览器 Origin。生产默认 Secure Cookie 和 HSTS，需由 HTTPS 反向代理提供入口。
- 图书编辑提交 version，旧版本保存返回 409。前端身份切换会重新挂载业务页面，避免残留上一身份的数据。
- CSV 面向电子表格阅读，将公式前缀作为文本导出。该文本策略不保证第三方工具再次改写文件后仍保持安全。

## 费率与升级

新借阅保存借出时的每日逾期费率，后续调价只影响新借阅。归还、遗失登记和扫描任务使用同一快照。已结清/豁免的金额从累计应收中扣除，继续逾期只收差额。

迁移 004 为已有借阅采用升级时数据库中保存的费率补齐快照。旧库没有历史费率版本，因此无法自动重建更早的调价规则，也不会自动修改已经结清的历史账单。上线前需由业务方核对既有异常账单。

迁移 004 还增加图书版本、认证限流表、借还日期索引及默认菜单授权修复。所有迁移在启动时执行；升级前先备份数据库。

## 部署

项目运行基线为 Node.js >=22.20.0，CI 使用 22.20.0。在构建环境执行：

```bash
npm ci
npm run quality
npm run test:e2e
```

生产配置至少包含独立的 `DB_PATH`、`COOKIE_SECURE=true`，首次空库启动另需 `INITIAL_ADMIN_PASSWORD`（至少 12 字符）。运行 `npm start`。生产入口必须提供 HTTPS。

开发和生产数据库带环境标记，禁止交叉使用。旧库未标记时，生产启动检查已知演示账号口令；发现后拒绝启动。不会自动删除账号或修改密码。

`TRUST_PROXY` 留空时不信任转发头；有反向代理时只填写受控网段，例如 `loopback`。不要直接填写 true 或信任任意来源。代理应保留正确 Host 并把客户端 IP 写入 X-Forwarded-For。

## 备份与恢复

```bash
npm run db:backup -- /srv/library/library.db /srv/library-backups
npm run db:restore -- /srv/library-backups/library-时间与编号.db /srv/library-restored/library.db
```

备份使用 SQLite 在线备份 API，包含尚未 checkpoint 的 WAL 数据。新备份执行完整性和外键验证，转为独立文件后再按 BACKUP_KEEP 轮换（默认 14 份）；恢复拒绝覆盖现有文件。恢复到新路径、验证业务数据后，停止原服务，修改 DB_PATH 指向恢复库再启动。

备份含个人信息，应限制目录权限、加密异地副本。仓库提供工具，不会自动安装操作系统定时任务或上传到未指定的存储服务。

## 健康和监控

- `GET /api/health`：实际读取数据库；不可用返回 503。
- `GET /api/health/live`：进程存活检查。
- `GET /api/admin/operations`：需要 settings.manage，返回请求数、5xx 数量、平均/最大耗时、内存、进程存活时间、任务最近成功/失败信息。
- 生产 HTTP 日志为 JSON，包含请求 ID、方法、无查询参数的路径、状态、耗时和来源 IP；不记录密码、请求体或会话令牌。

## 需要部署或业务信息才能完成的事项

| 事项 | 仍需提供或决定 |
| --- | --- |
| HTTPS 与进程托管 | 生产域名、证书、服务器平台和代理/守护进程配置 |
| 异地备份与告警 | 存储目标、加密密钥管理、定时频率、保留期限、告警平台及接收人；需在目标环境执行恢复演练 |
| 历史费用核对 | 历史调价记录和已确认的异常账单，无法从旧数据库精确反推 |
| 容量与高可用 | 目标馆藏量、活跃读者、峰值并发、可接受停机和恢复时间；目前仍为单实例 SQLite，不宣称多实例容灾能力 |
| 跨项目公共库发布 | 本仓库明确以 packages/shared 为唯一源码并使用 npm workspaces；其他项目如需共同更新，需确定统一仓库或私有 npm 发布目标 |
| 审计及个人信息保留 | 组织规定的保留期限、归档和删除规则，不能擅自清理生产历史数据 |

每次交付同时核对本机测试和 GitHub Actions 的实际结果；自动化回归不替代生产容量验收。
